# 根因分析：OpenHarmony x86_general（QEMU/virtio-gpu/swrast）截图全黑

> 本文是 2026-10-19 至 10-20 两轮排查的最终结论，供后续项目参考，避免重复
> 踩坑。排查过程的证据见 evidence/ 与 logs/。

## 一句话结论

GL/软件渲染的客户端向 dumb buffer 支撑的 EGLSurface 输出的像素会整体丢失：
渲染调用链正常，缓冲也在正常流转，但最终内存里没有像素。CPU 渲染路径
（mmap 写入）的像素完好。系统里最主要的 GL 客户端是 SystemUI——它走 GL
路径画面就是全黑，走 CPU 路径就是 6.5 万色的锁屏界面。

## 因果链（按时间顺序）

1. OHOS 的 clang 编译 musl 时默认带 `-femulated-tls`，mesa 的 emutls 地址表
   因此按副本隔离，`glGetString` 始终返回 null。修复：用
   `-fno-emulated-tls` 重编 mesa 的 10 个库（已包含在镜像中）。
2. wrapper libEGL 的 HiLogPrint JUMP_SLOT 在 appspawn 沙箱里懒解析失败，
   GOT 保持初值，首次调用时跳转到无效地址产生 SEGV；
   BlobCache::WriteToDisk 有同样的问题。修复：在 wrapper 内提供本地 stub
   符号，并在 BlobCache 的四处调用上短路（v4 版本）。
3. 这个缺陷在系统已运行一段时间、再热替换组件的环境下，表现为 SystemUI
   崩溃循环或挂起；在完整冷启动的环境下则表现为一次无感的 eglInitialize
   失败，ArkUI 自动回退 CPU 渲染——这正是 10-19 出现彩色锁屏的偶然原因。
4. 10-20 复现失败后，问题被定位成明确的分层：EGL 初始化成功（GL 路径）
   画面为黑，失败（CPU 路径）画面为彩色。于是在 wrapper 里加入了由标记
   文件控制的 eglInitialize 强制失败（`/data/egl_no_init`），把偶然现象变成
   确定行为。
5. 显示侧另有独立卡点（与截图无关，同期排查）：内核 virtio_gpu 主平面格式表
   缺少 ARGB8888 导致 EINVAL，已补上；composer HAL 从不设置 SRC_*/CRTC_*
   几何属性导致 scanout 尺寸为 0，也已补上。

## 已验证的机制（不必重复排查）

| 事实 | 证据 |
|------|------|
| GL 写入丢失：CPU mmap 与 QEMU 资源 iov 指向不同的内存 | drmprobe 写入梯度后调用 SetCrtc，QEMU trace 收到全部 transfer/scanout/flush 但画面不变；mapper mmap 读回却有内容 |
| `/dev/fb1` 的 write() 不标记 deferred-io damage | 内核 fb_io_write 源码是纯 memcpy |
| fbcon 自身的重绘是把 fb1 内容送上 QEMU 屏幕的唯一机制 | console 输出引发滚动时，dd 写入的内容随之显示（22:18 实验） |
| composer 的 plane commit 与 fbcon 重绘互相争抢 plane | set_scanout 交替出现 + 覆盖实验 |
| QEMU screendump 的内容等于 virtio-gpu scanout 的内容 | 向 fb1 写 0，屏幕对应区域变黑 |
| snapshot_display 走 RenderService 内部渲染，不依赖 composer/DRM | composer 完全停止时快照依然是彩色 |
| 结束 render_service 后不可恢复（vsync 与会话链断裂），重新冷启动可以恢复 | 多轮实验 |

## 遗留问题（未解决，按优先级排列）

1. 用户态 dumb buffer 的 sgt/QEMU iov 与 mmap 页不一致：解决之后可以删除
   `/data/egl_no_init` 恢复 GL 全速路径，硬件屏显示也有望直接打通。
2. 硬件屏显示：镜像到 fb1、再借 console 输出触发推送的旁路已写进 HAL
   （标记文件 `/data/hdi_mirror` 启用，曾验证 91% 像素能显示到屏幕），但被
   RenderService 的 present 生命周期停摆（启动后一段时间停止出帧）挡住。
3. RenderService 与 composer 的会话生命周期：composer 退出后
   RenderService 的重新握手不完整（vsync worker 不重启，present 停摆）。
