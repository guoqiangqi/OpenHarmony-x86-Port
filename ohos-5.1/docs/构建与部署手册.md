# 构建与部署手册（x86_general 显示修复版）

## A. 从交付包部署（推荐，最快）

1. `tar xzf images/OpenHarmony-5.1.0-x86_general-images-20261020-displayfix.tar.gz`
2. `bash disk_assemble.sh /path/to/ohos_disk.img`（需要 sgdisk/gdisk、grub-mkstandalone、dd）
3. 用 tools/launch_qemu.sh 启动（或使用 USAGE.md 第 3 节的等价命令）
4. 按 USAGE.md 第 4 节的标准启动流程验证截图不少于 60,000 色

交付包里附有组装好的成品盘 `images/ohos_disk_20261020.img`，跳过组装步骤即可
直接启动，已经过端到端验证。

## B. 增量重编（修改补丁后更新到镜像）

前提：源码树 `/root/OpenHarmony/5.1-Release`，Ninja 用 `/root/oh_env/bin/ninja`
（pip 安装的版本），调用时必须带 `-w dupbuild=warn`。

```bash
cd /root/OpenHarmony/5.1-Release/out/x86_general

# EGL wrapper（platformsdk/libEGL.so）
/root/oh_env/bin/ninja -w dupbuild=warn graphic/graphic_2d/libEGL.so

# composer HAL（注意：运行时实际加载的是 system 分区 /vendor/lib64/ 下这份）
/root/oh_env/bin/ninja -w dupbuild=warn opc_soc_products/x86_general/libdisplay_composer_vendor.z.so

# 内核模块（三个模块必须在同一次 make 调用里编译；改 kernel/linux/linux-6.6 后
# 先同步到 out/x86_general/kernel/src_tmp/linux-6.6 再编）
cd /root/OpenHarmony/5.1-Release/out/x86_general/kernel/src_tmp/linux-6.6
export PATH=/root/OpenHarmony/5.1-Release/prebuilts/clang/ohos/linux-x86_64/llvm/bin:$PATH
export DEVICE_NAME=x86_general PRODUCT_COMPANY=opc PRODUCT_PATH=vendor/opc/x86_general
make LLVM=1 LLVM_IAS=1 KBUILD_OUTPUT=/root/OpenHarmony/5.1-Release/out/x86_general/kernel/OBJ/linux-6.6 \
  drivers/virtio/virtio_dma_buf.ko drivers/gpu/drm/drm_shmem_helper.ko drivers/gpu/drm/virtio/virtio-gpu.ko -j$(nproc)
```

部署到 guest（hdc 连通之后）：

```bash
hdc file send <产物> /data/local/tmp/ && hdc shell "mount -o remount,rw / && \
  cp /data/local/tmp/libEGL.so /system/lib64/platformsdk/libEGL.so && sync"
# virtio-gpu.ko 部署到 /system/lib/modules/virtio-gpu.ko（需重启 guest 生效）
# composer HAL 部署到 /system/vendor/lib64/libdisplay_composer_vendor.z.so
#   （注意是 system 分区里的 /vendor 目录）
```

更新任何图形组件之后都必须重新启动 QEMU：在已运行的系统里直接替换，
wrapper 会触发崩溃循环（见根因分析文档）。

## C. 全量源码构建（仅在重建整套基线时）

参考 vendor_opc 的流程：`./build.sh --product-name x86_general --ccache`
（Ubuntu 24.04 需要 Python 3.10 虚拟环境和 glibc 兼容补丁，细节见源码树
build/config）。全量构建的产物不包含本包对 mesa、wrapper 和内核的修复——
除非把第 B 节涉及的补丁全部编入后再组装磁盘；日常迭代建议用第 B 节的增量
编译配合 disk_assemble.sh。

## D. 相关的标记文件开关（都在 guest 的 /data 下）

| 标记文件 | 作用 | 默认 |
|----------|------|------|
| `/data/egl_no_init` | 存在时 eglInitialize 强制失败，全系统走 CPU 渲染（截图不黑的关键） | 存在（不要删除） |
| `/data/hdi_mirror` | 存在时 composer 把客户端 buffer 镜像到 /dev/fb1 并跳过 plane commit（硬件屏旁路实验） | 不存在 |
